# مدیار | Mediar

سورس برنامهٔ محلی اندروید برای یادآوری و ثبت آگاهانهٔ مصرف دارو با تگ NFC. داده‌ها روی دستگاه هستند؛ برنامه مجوز اینترنت ندارد. این مخزن شامل Gradle Wrapper و workflow ساخت APK آزمایشی است.

## ساخت APK بدون Android Studio

1. ZIP سورس را از حالت فشرده خارج کنید. **محتویات پوشهٔ `Mediar`** شامل `gradlew`، `settings.gradle.kts`، پوشه‌های `app`، `gradle` و `.github` را در **ریشهٔ** مخزن GitHub بگذارید؛ خود پوشهٔ `Mediar` نباید یک لایهٔ اضافی باشد. در وب GitHub: مخزن تازه، `Add file → Upload files`، تمام فایل‌ها و پوشه‌ها، commit روی شاخهٔ `main`. فایل مخفی `.github/workflows/build.yml` را هم بررسی کنید.
2. تب **Actions → Build Mediar APK → Run workflow** را بزنید؛ push روی `main` هم خودکار اجرا می‌شود. اگر GitHub برای اولین بار دربارهٔ فعال‌کردن Actions پرسید، آن را فعال کنید.
3. پس از سبزشدن job، در صفحهٔ run بخش **Artifacts** فایل `mediar-debug-apk` را دانلود و استخراج کنید. فایل `app-debug.apk` را به گوشی منتقل کنید و باز کنید. اگر اندروید پرسید، فقط برای برنامه‌ای که با آن APK را باز می‌کنید «نصب از این منبع» را مجاز کنید. APK آزمایشی با debug key خود GitHub Runner امضا می‌شود و کلید شخصی لازم ندارد؛ نگه‌داشتن داده در ارتقاهای آینده به استفاده از امضای یکسان نیاز دارد. قبل از نصب بیلد جدید پشتیبان بگیرید.
4. داخل برنامه PIN بسازید؛ از مدیریت دارو و برنامه اضافه کنید. برای یادآور، مجوز اعلان و در صورت نیاز مجوز **Alarms & reminders** را در تنظیمات گوشی بدهید. NFC گوشی باید روشن باشد. برای ضبط صدای شخصی، مجوز میکروفون لازم است. نبود مجوز آلارم دقیق باعث تأخیر احتمالی می‌شود؛ نبود اعلان مانع نمایش برنامهٔ امروز در اپ نیست.

ساخت محلی، در محیط دارای Android SDK و JDK 17: `./gradlew testDebugUnitTest assembleDebug`. APK در `app/build/outputs/apk/debug/app-debug.apk` خواهد بود.

## آماده‌سازی تگ‌ها

1. در «مدیریت → گروه‌ها و نوشتن NFC» گروه‌هایی مثل صبح و شب بسازید. دارو را اضافه کنید؛ در برنامهٔ آن، زمان، مقدار **هر نوبت** و گروه را انتخاب کنید.
2. در صفحهٔ تگ، نوع «دارو»، «جعبه/گروه» یا «گزارش امروز» و هدف را انتخاب کنید؛ «تگ جدید بنویس» را بزنید و تگ خالی سازگار با NDEF را به گوشی نزدیک کنید. روی تگ فقط `v1:` به‌علاوهٔ شناسهٔ تصادفی ۱۲۸ بیتی با نوع MIME اختصاصی ذخیره می‌شود. برچسب پزشکی یا نام دارو روی آن نیست. تگ موجود را می‌توان غیرفعال یا دوباره تخصیص داد؛ برای جایگزین نیز تگ دیگری بنویسید و قدیمی را غیرفعال کنید.
3. اسکن اول فقط وضعیت را اعلام می‌کند. گوشی باید برداشته شود؛ **فقط بعد از callback جداشدن تگ** اسکن دوم تا ۳۰ ثانیه معتبر است. روی گوشی‌هایی که callback قابل اتکا ندارند، دکمهٔ بزرگ «خوردم» در نتیجهٔ اسکن را بزنید. اسکن دوم تگ جعبه فقط صفحهٔ تأیید را باز می‌کند؛ «همه را خوردم» یا انتخاب موارد، اقدام نهایی است. تگ «گزارش امروز» هیچ ثبت مصرفی انجام نمی‌دهد.
4. اگر نوبت مبهم باشد، زمان مربوط را صریح انتخاب کنید. مصرف پیش از موعد نزدیک با زمان واقعی و برچسب زودهنگام ثبت می‌شود. مصرفی که به نوبت قابل انتخاب وصل نیست با تأیید جداگانه به‌عنوان «خارج از برنامه» ثبت می‌شود؛ برنامه به‌طور خودکار تغییر نمی‌کند. هیچ توصیهٔ پزشکی دربارهٔ ایمن‌بودن دوز زودهنگام یا اضافه ارائه نمی‌شود.

## منطق و داده

- SQLite با نسخهٔ schema، جداول مستقل دارو، نسخهٔ برنامه، نوبت، رویداد مصرف، اصلاح، گروه، تگ، موجودی و تنظیمات. زمان واقعی مصرف و زمان ثبت جدا هستند. شناسهٔ نوبت از نسخهٔ برنامه، تاریخ و شناسهٔ زمان ساخته می‌شود. ویرایش برنامه نسخهٔ جدید می‌سازد. رخدادهای تاریخی و داروهای بایگانی‌شده حذف نمی‌شوند.
- فهرست نوبت‌های نامشخص، **عدم مصرف قطعی** نیست. اعلام صریح «مصرف نکردم» جدا ثبت می‌شود. قید یکتای partial در SQLite و transaction، ثبت دوبارهٔ یک نوبت را مهار می‌کنند. اصلاح منطقی رخداد تاریخچه را نگه می‌دارد و موجودی از adjustmentها منهای مصرف‌های اصلاح‌نشده محاسبه می‌شود.
- برنامه‌های روزانه، روزهای هفته (۱ دوشنبه تا ۷ یکشنبه)، هر N روز و چرخهٔ مصرف/استراحت با تاریخ شروع و پایان اختیاری پیاده شده‌اند. نوبت‌ها بر اساس زمان محلی و منطقهٔ زمانی فعلی بازسازی می‌شوند. تاریخ‌های قبلی حفظ می‌شوند. تخمین روزهای باقی‌مانده از الگوی امروز صرفاً تقریبی است.
- برای هر نوبت PendingIntent مستقل ساخته می‌شود؛ تکرار محدود است و با ثبت همان نوبت متوقف می‌شود. گیرندهٔ boot، آپدیت، تغییر ساعت، منطقهٔ زمانی و مجوز آلارم برنامه را بازسازی می‌کند. اعلان روی صفحهٔ قفل نام دارو ندارد. صدا هنگام **اسکن داخل برنامه** پخش می‌شود؛ اعلان سیستم هنگام هشدار پخش می‌شود تا صدای ضبط‌شده و TTS با آن تداخل نکنند.
- فایل پشتیبان `.mediar` یک ZIP نیست؛ JSON شامل داده‌ها و فایل‌های صوتی با PBKDF2-HMAC-SHA256 و AES-256-GCM به‌صورت یکپارچه رمز و احراز اصالت می‌شود. بنابراین هیچ مسیر آرشیوی استخراج نمی‌شود و zip-slip مطرح نیست. هنگام بازیابی رمز/اصالت و اندازه/نام فایل‌های صوتی بررسی می‌شود و درج داده در یک transaction است. از گذرواژهٔ بلند نگهداری کنید؛ PIN چهاررقمی جای رمزگذاری فایل یا قفل سیستم را نمی‌گیرد.

## محدودیت‌های نسخهٔ حاضر و آزمون

این سورس در محیط ساخت این گفتگو **APK موفق و تست اجراشده ندارد**: Gradle Wrapper درست شروع شد ولی دانلود `gradle-8.13-bin.zip` با `Network is unreachable` متوقف شد و Android SDK محلی هم موجود نبود. workflow باید روی GitHub اجرا شود؛ سبزشدن آن هنوز تأیید نشده است. آزمون‌های JUnit منطق زمان‌بندی، چند نوبت، نسخه، مرز روز و گیت اسکن در `app/src/test` هستند. آزمون SQLite برای جلوگیری از تکرار و بازگشت موجودی در `app/src/androidTest` به گوشی/شبیه‌ساز احتیاج دارد و workflow فعلی فقط unit test را اجرا می‌کند.

این نسخه همهٔ جزئیات درخواست را کامل نمی‌کند: متن بخش مدیریت عمدتاً فارسی است و انگلیسی فعلاً در عنوان و ناوبری اصلی فعال است؛ تعویق دستی اعلان (snooze)، صدای سفارشی هنگام آلارم پس‌زمینه، انتخاب تاریخ/ساعت مصرف گذشته، بازیابی فراموشی PIN بدون پشتیبان، و آزمون end-to-end NFC هنوز پیاده/تأیید نشده‌اند. نصب و استفادهٔ واقعی برای دارو را تا بعد از build سبز و آزمون روی گوشی با تگ واقعی محدود به آزمایش کنید.

### چک‌لیست گوشی واقعی

- تگ دارو را در حالت بسته‌بودن اپ و سپس در حالت باز اسکن کنید؛ اولین تماس فقط وضعیت باشد. چند callback در یک تماس نباید مصرف بسازد؛ جداسازی کامل و اسکن دوباره یا دکمهٔ خوردم باید دقیقاً یک رخداد ثبت کند.
- تگ گروهی را دوبار بخوانید؛ تا قبل از لمس دکمهٔ نهایی هیچ دارویی ثبت نشود. بعد از ثبت، دوبارخوانی مجدد نباید دوز دوم همان نوبت بسازد.
- گوشی را ری‌استارت و مجوز آلارم/اعلان را تغییر دهید؛ یادآورهای نوبت بعد را بررسی کنید. تگ‌ها را پس از پشتیبان‌گیری و بازیابی روی نصب آزمایشی دوباره بخوانید.
- صدای فارسی آفلاین نصب‌شده و نصب‌نشده، حالت بدون صدا، TalkBack، چیدمان راست‌چین، حالت تیره و اندازهٔ متن بزرگ را بررسی کنید.

نسخه‌های ساخت: AGP 8.13.2، Gradle 8.13، JDK 17، Kotlin 2.2.20 و Compose BOM 2026.09.00. مستندات رسمی: [AGP](https://developer.android.com/build/releases/agp-8-13-0-release-notes)، [Compose BOM](https://developer.android.com/develop/ui/compose/bom)، [Exact alarms](https://developer.android.com/develop/background-work/services/alarms).
